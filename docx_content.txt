1. Project Overview
1.1 Problem Statement
Indian government grievance portals receive thousands of cybercrime complaints daily — phishing, UPI fraud, OTP scams, ransomware, cyber stalking, and defamation. Current systems depend on manual review and keyword tagging, causing delays, poor prioritization, and inability to detect fraud networks or emerging crime patterns.
Core Pain Points:
Manual categorization — officers read each complaint individually
No semantic understanding — same fraud described differently goes undetected
No fraud network detection — same UPI ID used in 50 complaints never linked
No support for image-based complaints — screenshots rejected
No decision support — officers have no AI-assisted recommendations
1.2 Proposed Solution
An end-to-end AI pipeline that accepts text and image complaints, extracts entities using Mistral 7B (Ollama), builds a Neo4j knowledge graph, stores semantic embeddings in ChromaDB, and uses Graph RAG + Corrective RAG (CRAG) to provide intelligent officer recommendations — all running 100% locally on the developer machine.

6. Key Notes for Viva / Presentation
Be prepared to explain these points clearly during your final year project viva:

Why Graph RAG over basic RAG — entity-linked complaint retrieval finds fraud networks that semantic search alone cannot detect
Why Corrective RAG — prevents wrong recommendations when historical data is scarce, handles new crime types gracefully using local knowledge base
Why Mistral via Ollama — government data privacy requirements, no internet dependency, runs on existing RTX 2050 hardware
Why EasyOCR over Tesseract — better Hindi+English support, higher accuracy on mobile screenshots common in cybercrime complaints
Why Neo4j for graph — native graph traversal is far faster than SQL JOINs for multi-hop relationship queries
Why SBERT all-MiniLM-L6-v2 — 384 dimensions balances accuracy and speed, fits within 4GB VRAM constraint
The CRAG paper reference — Yan et al., Corrective Retrieval Augmented Generation, 2024
Why single Mistral call for all extraction — minimizes latency; multiple calls would add 15–25 seconds per complaint
